# 読書記録

読んだ本と読みたい本を、表紙付きで記録しておくための個人用アプリ。スマホのブラウザで開き、ホーム画面に追加して使う。

- 記録はすべて端末の中（IndexedDB）に保存され、サーバーには送られない
- タイトルで検索すると、表紙・著者・出版社が自動で入る（楽天ブックスAPI）
- 感想は音声入力でも書ける
- 読みたい本が図書館にあるか確認できる（カーリルAPI）

## 使い方

<https://yamada724-a11y.github.io/reading-log/> を開き、ブラウザのメニューから「ホーム画面に追加」する。

初回だけ、右上の設定から楽天ブックスAPIのキーを登録する（下記）。

## APIキーについて

**キーはこのリポジトリには含まれていない。** アプリの設定画面から入力し、その端末のブラウザ内（localStorage）にのみ保存される。

| キー | 取得先 | 用途 |
|---|---|---|
| アプリケーションID / アクセスキー | <https://webservice.rakuten.co.jp/> | タイトル検索・表紙の取得 |
| appkey | <https://api.calil.jp/api/dashboard/> | 図書館の蔵書確認 |

楽天のアプリ登録では「許可されたWebサイト」に、アクセス元のドメインを1行ずつ登録する必要がある。登録がないとAPIは403/503を返す。

```
yamada724-a11y.github.io
lvh.me
```

`lvh.me` はローカル開発用（127.0.0.1に解決される公開ドメイン）。`localhost` は登録できない。

## 開発

ビルドツールは使わない。素のHTML / CSS / ESモジュールのみ。

```bash
python -m http.server 8765 --directory .
```

`http://lvh.me:8765/` を開く（`localhost` だと楽天APIが弾かれるため）。

### 更新するとき

push すれば反映される（オンラインなら常に最新を取りに行く作りのため）。

ただし `sw.js` の `SHELL` に載せるファイルを増減したときは、同ファイル先頭の `CACHE_VERSION` を1つ上げること。古いキャッシュを捨てるための番号。

### ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | 画面のガワ |
| `style.css` | デザイン一式 |
| `app.js` | 画面遷移と操作 |
| `db.js` | 端末内保存（IndexedDB） |
| `api.js` | 楽天 / openBD / カーリルの呼び出し |
| `sw.js` | オフライン動作 |
